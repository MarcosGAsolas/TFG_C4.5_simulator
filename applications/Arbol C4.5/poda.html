Simulación Árbol C4.5 Poda

Poda

Información general

La poda es una fase posterior a la construcción del árbol que busca reducir ramas demasiado específicas o poco fiables. Su objetivo es mejorar la generalización del modelo y evitar que el árbol aprenda ruido del dataset de entrenamiento.

En C4.5, primero se puede construir un árbol completo con las reglas de selección de atributos y umbrales. Después, la poda revisa subárboles y decide si conviene sustituirlos por una hoja o mantenerlos.

La idea principal es comparar el comportamiento estimado del subárbol frente al de una clasificación más simple. Si la rama añade complejidad sin aportar una mejora suficiente, se elimina.

En esta sección puedes cargar datasets y recorrer la simulación del árbol igual que en la construcción C4.5, usando la visualización para analizar qué partes podrían ser candidatas a poda.

Algoritmo de poda

Entrada:

  • Árbol de decisión construido \(T\)
  • Dataset usado para estimar el error de cada nodo

Salida:

  • Árbol de decisión podado \(T'\)

Fórmula de error estimado:

Para cada hoja \(i\) del subárbol, si llegan \(N_i\) registros y predice incorrectamente \(E_i\) de ellos, su error estimado individual es:

\[ Error_{hoja_i} = \frac{E_i + 0.5}{N_i} \]

El error estimado total del subárbol se obtiene mediante una media ponderada. Cada hoja contribuye según la proporción de registros que recibe respecto al total \(N\):

\[ Error_{subarbol} = \sum_{i=1}^{L} \frac{N_i}{N} \cdot Error_{hoja_i} \]

De forma equivalente, usando la corrección simplificada de \(0.5\) por hoja:

\[ Error_{subarbol} = \frac{\sum_{i=1}^{L} E_i + 0.5 \cdot L}{N} \]

Si el subárbol se sustituye por una única hoja, el error estimado de esa hoja simplificada es:

\[ Error_{hoja} = \frac{E_{hoja} + 0.5}{N} \]

  • \(L\) es el número de hojas del subárbol evaluado.
  • \(N_i\) es el número de registros que llegan a la hoja \(i\).
  • \(N\) es el número total de registros que llegan al nodo evaluado.
  • \(E_i\) representa los errores reales de la hoja \(i\).
  • \(E_{hoja}\) son los errores reales al sustituir el subárbol por una única hoja.
  • La media ponderada muestra la contribución de cada hoja al error final del subárbol.

Algoritmo:

  1. Recorrer el árbol desde las hojas hacia la raíz, evaluando primero los nodos más profundos.
  2. Para cada nodo interno, identificar todas las hojas que forman su subárbol y calcular los registros que llegan a cada una de ellas.
  3. Para cada hoja \(i\) del subárbol, determinar la clase mayoritaria que predice y calcular sus errores reales \(E_i\).
  4. Calcular el error estimado individual de cada hoja con \(Error_{hoja_i} = \frac{E_i + 0.5}{N_i}\).
  5. Calcular el error estimado total del subárbol mediante la media ponderada \(Error_{subarbol} = \sum_{i=1}^{L} \frac{N_i}{N} \cdot Error_{hoja_i}\).
  6. De forma equivalente, expresar ese mismo error como \(Error_{subarbol} = \frac{\sum_{i=1}^{L} E_i + 0.5 \cdot L}{N}\).
  7. Calcular la clase mayoritaria entre todos los registros que llegan al nodo interno. Esta será la clase que predeciría el nodo si se sustituyera todo el subárbol por una única hoja.
  8. Calcular los errores reales de esa hoja simplificada: \(E_{hoja} = N - \max(\text{cantidad de registros por clase})\).
  9. Calcular el error estimado de la hoja simplificada con \(Error_{hoja} = \frac{E_{hoja} + 0.5}{N}\).
  10. Comparar ambas alternativas: si \(Error_{hoja} \leq Error_{subarbol}\), el subárbol se poda y el nodo interno se reemplaza por una hoja que predice la clase mayoritaria. Si \(Error_{hoja} > Error_{subarbol}\), el subárbol se conserva.
  11. Repetir el proceso hasta revisar todos los nodos internos candidatos.
  12. Devolver el árbol resultante tras eliminar las ramas innecesarias.

Por ejemplo, si un nodo tiene tres hojas, en la expresión equivalente la corrección por complejidad del subárbol será \(0.5 \cdot 3 = 1.5\). Por tanto, aunque el subárbol cometa menos errores reales que una única hoja, deberá compensar también la penalización asociada a mantener sus tres hojas.

Requisitos del archivo
  1. Formato: archivo CSV separado por comas.
  2. Cabecera: la primera fila debe contener los atributos.
  3. Filas: el dataset no puede tener más de 150 filas de datos.
  4. Columnas: el dataset no puede tener más de 25 columnas.
  5. Cabecera completa: la cabecera no puede contener columnas vacías.
  6. Filas: todas las filas deben tener el mismo número de columnas.
  7. Valores: no puede haber valores vacíos.
  8. Formato de columnas: cada columna debe tener todos los datos del mismo formato.
  9. Formatos permitidos: los datos pueden ser numéricos, booleanos o categóricos.
  10. Clase: la última columna debe ser la clase objetivo.
  11. Valores de clase: la última columna debe contener exactamente dos valores distintos.
